# 照片月历 — 项目开发约定

## 项目定位
移动端 H5 轻制作工具：把相册照片整理成可分享的月历图。
不是打卡工具、不是云相册、不是 AI 相册管理器。

## 基线文档
- PRD 基线：docs/PRD.md（V1.0，已冻结）
- 进展与已知坑：docs/PROGRESS.md
- 任务清单：docs/TASKS.md
- 任何新需求先记入 PRD 变更记录，不直接改基线。

## V1 范围（已完成，待部署）
- 单月月历编辑：今日高亮、月份切换、一格一张、选图/替换/删除/查看
- EXIF 本地解析，非阻塞提示（不一致默认填入当前格）
- IndexedDB 本地草稿（只存压缩图 Blob）
- 3 套模板 + 背景色 + 照片滤镜 + 自定义背景图（自动暗化）
- 导出：单月 3:4 竖版（主推）、全年横版 4×3 Beta、全年竖版 3×4 Beta
- 复制小红书文案、匿名埋点（useTrack）

## 坚决不做（出现即拒绝）
AI 自动选图/回填、AI 付费意愿问卷、账号、云端、跨设备同步、文字备注、AI 文案、
自定义时间段合集、拼图、多图格子、视频导出、强制水印、
饱和度/透明度滑杆、社区互动、多人协作、heic2any（V1 不引入）。

## 技术约束（踩坑沉淀）
1. **EXIF**：iPhone Safari 上传时系统会剥离 EXIF，主路径**不要依赖 EXIF**，读不到也要能直接填图。
2. **HEIC**：桌面浏览器不支持，报错时给友好提示即可。
3. **Canvas 导出**：
   - 绝对不用 `html2canvas`。
   - **禁用 `ctx.filter = 'blur(...)'`**，iOS Safari 完全不支持，直接用“原图 + 黑色遮罩层”替代。
   - 画背景图时，需覆盖全屏，防止边缘漏色。
   - 排版逻辑：**顶部紧凑 + 底部留白**，不要垂直居中。
4. **保存图片**：iOS 中 `a.download` 存不到相册（只进文件 App），导出弹窗必须有“长按图片保存”的引导文案。
5. **草稿持久化**：所有保存（照片、样式、当前月份）走 `usePhotos.js` 的 `doSave`，用防抖 300ms，快照必须转为 plain object（Proxy 不能直接进 IndexedDB）。

## 编码规则
- 组件按职责拆：CalendarGrid / DayCell / StyleDrawer / ExportSheet / useExif / useDraftDB / useExportCanvas / useTrack
- 业务逻辑放 composables，不塞进模板
- 提交前过一遍 PRD 第 10 节验收清单

## 已知坑（改代码前先看）
- 微信内保存图片：长按保存，准备新窗口/复制链接兜底。
- IndexedDB 配额：只存压缩图，异常提示“导出后清理”。
- 埋点统计：`useTrack.js` 目前只有 `console.log`，后续接 API。
- Vite 运行期间新建文件可能不识别：重启 dev server。
