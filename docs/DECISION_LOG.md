本文件用于记录《照片月历》的重要产品决策，确保产品需求、交互设计和开发实现保持一致。

记录原则：

1. 只记录已经明确确认的决策。
2. 记录决策背景、最终方案和原因。
3. 尚未确定的事项不作为正式决策。
4. 决策发生变化时，新增记录，不覆盖历史记录。
5. 开发实现应遵循当前有效的决策。

## DEC-001：无 EXIF 照片的批量日期分配方案

- 日期：2026-11-26
- 所属版本：V1.1
- 状态：已确认

### 背景

部分手机照片无法读取 EXIF 拍摄时间。

如果要求用户逐张手动选择日期，批量导入的效率优势会明显降低。

### 备选方案

A. 按照片选择顺序填入连续空日期。

B. 每张照片手动选择日期。

C. 默认连续填入，同时允许拖动调整。

### 最终决策

采用 C 方案。

默认连续填入，同时允许用户拖动调整。

### 具体规则

1. 用户一次选择多张照片。
2. 有 EXIF 日期的照片优先使用拍摄日期。
3. 无 EXIF 日期的照片进入待分配列表。
4. 用户指定起始日期。
5. 系统按照照片选择顺序，将无 EXIF 照片依次分配到后续空日期。
6. 已有照片的日期默认跳过，不覆盖。
7. 用户可以在确认前拖动调整照片对应日期。
8. 用户确认后才正式写入月历。

### 决策原因

兼顾批量操作效率和用户对照片排列结果的控制权。

默认操作应尽量简单，同时保留足够的调整空间。

### 影响范围

- 批量照片导入。
- EXIF 日期识别。
- 日期分配逻辑。
- 手机端拖动交互。
- 电脑端拖动交互。
- 导入预览与确认。

### 验收依据

以《照片月历 V1.1 产品需求文档》中 IMP-BATCH-001 和 IMP-BATCH-002 的要求为准。

## DEC-002：V1.0 产品需求基线管理

- 日期：2026-11-26
- 所属版本：V1.1
- 状态：已确认

### 决策

V1.0 原始 PRD 作为历史基线保留，不直接覆盖。

后续需求变化通过新版本 PRD 和变更记录管理。

### 原因

保证产品发展过程可追溯，避免原始需求、后续调整和实际开发结果混在一起。

### 执行规则

1. V1.0 文档不直接覆盖。
2. 新增需求进入对应版本的 PRD。
3. 重要产品选择写入 DECISION_LOG。
4. 每次正式发布更新 CHANGELOG。
5. 开发进度和任务状态分别维护在 PROGRESS 和 TASKS 中。
