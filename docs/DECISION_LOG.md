# 产品决策记录（DECISION LOG）

本文件用于记录《照片月历》的重要产品决策，确保产品需求、交互设计和开发实现保持一致。

记录原则：

1. 只记录已经明确确认的决策。
2. 记录决策背景、最终方案和原因。
3. 尚未确定的事项不作为正式决策。
4. 决策发生变化时，新增记录，不覆盖历史记录。
5. 开发实现应遵循当前有效的决策。

## DEC-001：无 EXIF 照片的批量日期分配方案

- 日期：2026-11-26
- 所属版本：V1.1
- 状态：已确认

### 背景

部分手机照片无法读取 EXIF 拍摄时间。

如果要求用户逐张手动选择日期，批量导入的效率优势会明显降低。

### 备选方案

A. 按照片选择顺序填入连续空日期。

B. 每张照片手动选择日期。

C. 默认连续填入，同时允许拖动调整。

### 最终决策

采用 C 方案。

默认连续填入，同时允许用户拖动调整。

### 具体规则

1. 用户一次选择多张照片。
2. 有 EXIF 日期的照片优先使用拍摄日期。
3. 无 EXIF 日期的照片进入待分配列表。
4. 用户指定起始日期。
5. 系统按照照片选择顺序，将无 EXIF 照片依次分配到后续空日期。
6. 已有照片的日期默认跳过，不覆盖。
7. 用户可以在确认前拖动调整照片对应日期。
8. 用户确认后才正式写入月历。

### 决策原因

兼顾批量操作效率和用户对照片排列结果的控制权。

默认操作应尽量简单，同时保留足够的调整空间。

### 影响范围

- 批量照片导入。
- EXIF 日期识别。
- 日期分配逻辑。
- 手机端拖动交互。
- 电脑端拖动交互。
- 导入预览与确认。

### 验收依据

以《照片月历 V1.1 产品需求文档》中 IMP-BATCH-001 和 IMP-BATCH-002 的要求为准。

## DEC-004：批量导入支持两种日期安排模式

- 日期：2026-11-27
- 所属版本：V1.1
- 状态：已被 DEC-007 取代（不再执行）

### 背景

用户可能希望保留照片拍摄日期，也可能希望不考虑拍摄日期，只按选择顺序制作一组连续月历。

### 最终决策

批量导入提供两种可主动选择的模式：

1. 按拍摄日期：有 EXIF 日期的照片使用拍摄日期，无日期照片按选择顺序填入空日期。
2. 按选择顺序：忽略所有照片的 EXIF 日期，从指定起始日期按选择顺序填入空日期。

两种模式都允许确认前修改日期和调整顺序；已有照片日期不覆盖，冲突必须明确提示。

### 原因

拍摄日期只是自动化建议，不应成为限制用户创作顺序的规则。用户应能根据自己的整理目的决定日期来源。

## DEC-005：批量导入列表支持移除与格式错误隔离

- 日期：2026-11-27
- 所属版本：V1.1
- 状态：已确认

### 决策

1. 用户可在确认导入前从待导入列表移除任意单张照片。
2. 不支持或无法解码的文件显示错误状态，不允许编辑日期或调整顺序，也不允许导入。
3. 错误文件可以单独移除，不影响其他有效照片继续导入。
4. 成功写入月历后，照片仍可通过现有月历照片操作删除。

### 原因

批量导入应允许用户在确认前清理选择结果；单个异常文件不应污染整个导入流程。

## DEC-007：从指定日期格发起批量导入时优先锚定该日期

- 日期：2026-11-27
- 所属版本：V1.1
- 状态：已由 DEC-008 进一步修订

### 背景

用户点击某个日期格，意味着希望把选中的照片放在该日期。若该日期已有照片，批量导入不能静默跳过该日期并把照片排到后续空位。

### 最终决策

1. 从空白日期格发起选择：第一张有效照片默认安排到该日期。
2. 从已有照片日期的“更换”操作发起选择：第一张有效照片默认安排到该日期，并在预览中明确提示确认后会替换原照片。
3. 选择多张时，第一张照片优先锚定用户指定日期；其余照片仍优先使用 EXIF 日期，无 EXIF 的照片按选择顺序填入后续空日期。
4. 用户可以在确认前修改日期；若第一张照片被改到其他日期，则不再视为对锚点日期的替换。
5. 只有点击确认后才写入；取消不改变原有照片。
6. 非锚点日期已有照片时仍然禁止覆盖，必须调整日期。

### 原因

用户的点击位置是明确的操作意图。系统应尊重该意图，并将替换风险显式告知，而不是擅自改变目标日期。

### 同时废止的旧规则

DEC-001 中“已有照片的日期默认跳过，不覆盖”继续适用于普通批量导入及非锚点日期；用户明确点击的锚点日期适用本决策的替换规则。


## DEC-008：指定日期格发起批量导入时提供默认替换与跳过选项

- 日期：2026-11-27
- 所属版本：V1.1
- 状态：已确认

### 最终决策

1. 用户从某个日期格发起多张照片导入时，以该日期为起点，按用户选择顺序连续安排照片。
2. 默认选择“替换已有照片”：日期序列中已有照片的日期允许被新照片替换。例如从 18 日导入两张，分别安排到 18、19 日；两天已有照片时，确认后分别替换。
3. 用户可以切换为“只放入空格”：保留已有照片，按顺序跳过占用日期，将新照片放入后续空白日期。
4. 两种方式都必须在预览中展示最终日期；只有用户确认后才写入。
5. 此入口按指定日期和选择顺序安排，不使用 EXIF 日期覆盖用户明确指定的顺序。
6. 从普通“添加照片”入口发起批量导入时，仍优先按 EXIF 日期安排，无 EXIF 照片从指定起始日期填入空日期。

### 原因

点击日期格表达了明确的排列起点。默认替换最符合用户预期，同时保留不覆盖原照片的选择，避免系统擅自决定用户是否愿意覆盖。


## DEC-009：批量导入信息层级、排序与主界面辅助入口

- 日期：2026-11-27
- 所属版本：V1.1
- 状态：已确认

### 决策

1. 批量导入列表不展示冗长文件名，采用紧凑横向布局，缩略图、日期信息、安排日期控件和删除按钮保持同一行并垂直居中。
2. 普通「添加照片」入口中，读到日期时使用用户语言标注「照片拍摄日期」；未读到时标注「未读到拍摄日期」。不向普通用户展示 EXIF 术语。
3. 从指定日期格发起的批量导入按选择顺序安排，不使用拍摄日期改变用户明确指定的顺序。
4. V1.1 暂时移除批量列表拖动排序。触屏滑动与拖动容易冲突，当前实现不够可靠；日期仍可逐张修改。
5. 月份标题保留原位置和左右导航结构，点击标题后直接选择年月；选择界面内仅在当前展示月份不是本月时显示「回到本月」。不使用双击作为唯一返回方式。
6. 帮助入口移出月份导航区域，放在日历下方「添加照片」操作附近，以低强调文字链接呈现。「添加照片」入口保留。

### 原因

优先保证信息可理解、布局整齐和触屏操作可靠。辅助功能不应破坏月份导航结构；拖动排序不是完成导入的必要条件，不应以不稳定的交互换取功能数量。

### 影响范围

- 批量导入预览列表及触屏交互。
- 月份选择与返回当前月份。
- 主界面帮助入口。
- V1.1 PRD、任务和进度文档。
